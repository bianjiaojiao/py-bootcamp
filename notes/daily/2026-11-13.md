## 一、计划推倒重排：8 步拆分 → 7 个阶段

### 原来的计划（错的顺序）

```
config.py → loader.py → splitter.py → store.py → qa.py → 入口
```

**问题**：一上来就分 6 个文件，根本不知道每个文件为什么存在。

> 所以我当时一直在问"这个变量代表什么"、"为什么要建这个"——**因为我不知道整体长什么样，就被要求写零件。**

### 新计划（真实开发顺序）

| 阶段 | 做什么 | 产出 | 代码量 |
| --- | --- | --- | --- |
| **1** | **最小单体跑通**（读→切→向量→检索→问答，全在一个文件） | `step1_demo.py` | ~60 行 |
| 2 | 加阈值拒答 | +10 行 | |
| 3 | 加索引缓存（存 npz） | 拆成 2 个文件 | |
| 4 | **按分层拆分**（loader/splitter/store/qa） | 6 个文件 | |
| 5 | 加 HTTP 接口 | `serve.py` | +30 行 |
| 6 | 加评估 | `eval.py` | +50 行 |
| 7 | 加 README + 测试 | 文档 | |

### 核心原则

> **先单体，后重构。**
> **先写一个丑的、能跑的，再拆。**

为什么这样对：
- 单体阶段：注意力全在"逻辑对不对"，不用管文件怎么分
- 拆分阶段：已经知道整体了，拆的时候知道每个文件该放什么

## 二、搞懂 Skill 机制

完整专题：[36-Skill机制](../topics/36-Skill机制.md)

### 核心认知

> **Skill = 一个文件夹 + 一份说明书。不是打包程序，是"教模型怎么做事"。**

**证据**：本机的 `json-canvas` skill **只有一份 656 行的 SKILL.md，没有一个脚本、没有一行代码**。

### SKILL.md 分两半，用途完全不同

| 部分 | 作用 | 什么时候读 |
| --- | --- | --- |
| frontmatter（`name` + `description`） | **什么时候用我** | 启动时只读这段 |
| 正文 | **怎么用我** | 被选中才读 |

### 为什么必须分两半

```
几十个 skill 的 description 加起来 ≈ 几千字
正文加起来 ≈ 几万行
```

**只读 description 才不会撑爆上下文**——这叫"按需加载"。

### 触发流程

```
启动 → 扫 skills 目录 → 只读 description → 得到能力清单
   ↓
用户提需求 → 模型判断"哪个 skill 有用"
   ↓
命中 → 才读正文 → 正文说跑 scripts/xxx.py → 才跑
```

### 四种复杂度（本机真实分布）

| Skill | 构成 | 类型 |
| --- | --- | --- |
| `json-canvas` | 只有 SKILL.md | **纯知识**（无代码） |
| `qwen3-tts-local` | SKILL.md + 1 脚本 + 1 参考 | 知识 + 脚本 |
| `media-processor` | SKILL.md + 6 脚本 + 2 参考 | **工具箱** |
| `baoyu-format-markdown` | SKILL.md + ts + package.json | 带运行时 |

## 三、key 的现状（待处理）

```
agent-lab\.env      ← 有 key
course-rag\.env     ← 有 key
my-rag\.env         ← 有 key
```

**key 存在 3 份**，换一次要改 3 处。

### 解决方案（还没做）

```powershell
setx DEEPSEEK_API_KEY "sk-你的key"
```

提到系统环境变量后，所有项目 `os.getenv()` 都能读到 → 3 份 `.env` 里的 key 可以删掉。

## 四、今天学到的一个判断

| 概念 | 含义 |
| --- | --- |
| **项目** | 一整套程序，人跑 `python xxx.py` |
| **Skill** | 一份说明书（可带脚本），**模型自己读、自己跑** |

**关系**：项目可以包一层 SKILL.md 变成 skill。

**更进一步**：可以写"方法论 skill"——比如把"从零搭 RAG 的 7 个阶段 + 验收标准 + 常见坑"写成 SKILL.md。
**能写成说明书 = 真懂了。**
