## 🔑 今天最重要的 5 个认知

### 1. 模型只"说"不"做"

实验证明：问模型"现在几点"→ 它说"我没有实时时钟访问权限"；问"我桌面有什么文件"→ 它说"无法访问文件系统"。
**它住在 DeepSeek 的服务器上，能做的只有生成文字。** 所以"用工具"= 模型说"要做什么"，你的代码"真的做"。

### 2. `tool_calls` 是列表套字典

```
r.tool_calls                 → list   [ {...} ]        可能有多张申请单
r.tool_calls[0]              → dict   {'name','args','id','type'}
r.tool_calls[0]["args"]      → dict   {'a': 123, 'b': 456}
```

**同样是方括号**：列表里放数字（取第几个），字典里放字符串（取哪个键）。

### 3. `@tool` 把函数变成了对象

- 加 `@tool` 前：`function`，`add(1,2)` 能用
- 加 `@tool` 后：`StructuredTool`，`add(1,2)` **报错**，必须 `add.invoke({"a":1,"b":2})`
- `docstring` → `.description`，类型注解 → `.args`，**都是给模型看的**

### 4. `ToolMessage` 必须带 `tool_call_id`

对话是一个**消息列表**，三种身份：`HumanMessage`（人）/ `AIMessage`（模型）/ `ToolMessage`（工具）。
`tool_call_id` 是**配对编号**——模型一次可能申请 3 个工具，靠它知道"这个结果配哪张申请单"。

### 5. `ToolNode` + 一条回边 = L6 手写的 12 行

两边跑出来的 4 条消息**一模一样**：

```
HumanMessage → AIMessage(申请) → ToolMessage(结果) → AIMessage(最终回答)
```

而且图版还能**自动处理多个工具**（模型一次申请两个，ToolNode 全执行）。

## ⚠️ 今日踩的坑

| 坑 | 原因 | 记法 |
| --- | --- | --- |
| `ModuleNotFoundError: config` | 文件放在 `lessons/` 子目录，`from config import ...` 找不到 | **L 系列文件放 `agent-lab` 根目录** |
| 中文输出乱码（`��ʼ`） | 没 `import config`，Windows 控制台 GBK | 每个文件第一行 `import config` |
| `AttributeError: 'function' object has no attribute 'invoke'` | `mul` 没加 `@tool`，还是普通函数 | 用 `.invoke` 就必须先 `@tool` |
| `mul.invoke([call["args"]])` 多包一层列表 | `.invoke` 要**参数字典本身** | 不加外层方括号 |
| 把模型输出的大段文字当成"报错" | 判断标准错了 | 有 `Traceback`/`xxxError` 才是报错，否则是正常输出 |
