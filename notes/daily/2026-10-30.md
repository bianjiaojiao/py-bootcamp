## 📚 今日知识点

| 主题 | 一句话要点 |
| --- | --- |
| `except:` 裸捕获 | 会吞掉 `KeyboardInterrupt`、`NameError` 等所有异常 → 必须写具体类型（如 `except ValueError:`） |
| 函数定义了要调用 | "写了函数"≠"验证了行为"；可变默认参数必须靠两次调用才能看出坑 |
| `iter` / `next` | `next()` 取一个就消耗一个；剩下的用 `list()` 一次性拿走 |
| `__eq__` + `__hash__` | 两个必须成对重写：只写 `__eq__` 会让对象不可哈希（进不了 `set`） |
| `isinstance` 防护 | `__eq__` 里先判断类型，避免和别的类型比较时报错 |

## ⚠️ 今日易错点

1. `except:` 裸捕获 —— 掩盖真实错误，排查时最坑
2. 写了函数不调用 —— 等于没验证
3. 题目有两问只做第一问（12 题）
4. 猜数字里计数变量在"猜中"分支没 +1，靠打印时补 —— 后续判断就会差 1
5. 多行注释用 `''''`（四引号）不规范，建议逐行 `#`

### `18.1.py` 的两个 bug（详见错题本 十一）

```python
result = func(*args, *kwargs)     # ① 应该是 **kwargs
insert_time(a())                  # ② 加了括号：先执行 a()，装饰器根本没生效
```

正确写法：
```python
result = func(*args, **kwargs)

@insert_time
def a(): ...

a()          # 这时才打印「wan」+ 耗时
```

> **同一个"函数当值不加括号"的坑，这是第 2 次翻车**（第一次是 17.py 的 `target=add_100()`）。
