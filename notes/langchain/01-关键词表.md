# LangChain / LangGraph 关键词表（人话版）

> **用途**：读自己的代码时，遇到不认识的词就查这里。
> **原则**：每个词都配一句"人话" + 一个普通 Python 类比。
> **别背**：读代码时查、写的时候查，查十遍自然就记住了。

---

## 0. 先记住两张全景图

**LangChain 就是一条流水线：**

```
提示词模板 ──► 模型 ──► 消息 ──► 解析器 ──► 纯文本
                        ▲
                     工具（模型可以"请求"调用，但不执行）
```

**LangGraph 是另一层：**

```
状态(State) ──► 节点(Node) ──► 边(Edge) ──► 编译(compile) ──► 调用(invoke)
                    ↑                            │
                    └──── 循环可能回到这里 ◄──────┘
```

**只要记住这两张图，LangChain/LangGraph 的代码你都能"猜"出大概在干嘛。**

## 1. 模型相关

| 词 | 人话 | 类比 |
| --- | --- | --- |
| `llm` | 模型对象，一个"能对话的东西" | `f = open(...)` 里的 `f` |
| `ChatOpenAI` | 创建模型对象的**类** | `list()`、`dict()` |
| `get_llm()` | 我们自己的小函数，帮你把 key、base_url 配好 | 工厂函数 |
| `.invoke(输入)` | **调用一次**，等结果 | `函数(参数)` |
| `temperature` | 温度=随机性。0 最稳定，1 最大胆 | 有点像 `random.seed()` |
| `bind_tools([...])` | 把"工具清单"装备给模型 | 给函数加一个可选参数 |

## 2. 消息相关（最容易懵的一层）

| 词 | 人话 | 类比 |
| --- | --- | --- |
| `HumanMessage` | "用户说的话" | `{"role": "user", "content": ...}` |
| `AIMessage` | "模型说的话" | `{"role": "assistant", ...}` |
| `SystemMessage` | "系统设定"（人设、规则） | `{"role": "system", ...}` |
| `ToolMessage` | "工具执行的结果" | `{"role": "tool", ...}` |
| `.content` | 消息里的**文字** | `d["content"]` |
| `.tool_calls` | 消息里的**工具调用请求** | `d.get("tool_calls")` |
| `messages` | 一串消息 = 对话历史 | 一个 list |

> **为什么总要多写 `.content`？**
> 因为模型返回的**不是字符串**，是"消息对象"（里面装着文字、工具请求、token 用量等）。
> 只想要文字，就得 `.content`。这个对象身上有字段，和字典一样用 `.get()` 安全。

## 3. 提示词相关

| 词 | 人话 |
| --- | --- |
| `ChatPromptTemplate` | 提示词**模板**（带变量的模板字符串） |
| `.from_messages([...])` | 用一个消息列表"组装"模板 |
| `("system", "你是一位…")` | 一条系统消息（定人设） |
| `("human", "{question}")` | 一条用户消息，`{question}` 是**待填变量** |
| `.invoke({"question": "…"})` | 给变量填值 → 生成真正的提示词 |

## 4. 链 / LCEL

| 词 | 人话 |
| --- | --- |
| `chain` | 链：把几步串起来的一个整体 |
| `\|` | 管道符：**前一步的输出 → 后一步的输入** |
| `LCEL` | LangChain Expression Language，就是用 `\|` 拼链的那套写法 |
| `StrOutputParser()` | 解析器：把"消息对象"变成"纯文本" |
| `.with_structured_output(Model)` | 让输出变成 Pydantic 对象 |
| `method="function_calling"` | 用"函数调用"实现结构化（**DeepSeek 必须**） |

## 5. 工具

| 词 | 人话 |
| --- | --- |
| `@tool` | 装饰器：把普通函数变成"模型能用的工具" |
| docstring（`"""…"""`） | 工具说明，**模型靠它决定用不用这个工具** |
| `bind_tools([add])` | 告诉模型"你有这些工具" |
| `tool_calls` | 模型发来的调用请求，如 `[{'name':'add','args':{'a':1,'b':2}}]` |
| `TOOLS` | 工具列表（只是个普通 list） |
| `ToolNode(TOOLS)` | LangGraph 里负责**执行工具**的节点 |

> **最关键的一句**：模型**不会执行** `add`，它只发 `tool_calls`；真正执行的是 `ToolNode`（你的代码）。

## 6. 图 / LangGraph

| 词 | 人话 | 类比 |
| --- | --- | --- |
| `State` | 图里流动的"数据袋子" | 一个 dict |
| `TypedDict` | 规定这个 dict 有哪些键 | 给 dict 加"字段说明" |
| `Annotated[list, add_messages]` | "这个列表用**累加**的方式更新" | 相当于 `append` 而不是 `=` |
| `add_messages` | 累加函数（reducer） | `def f(a, b): return a + b` |
| `StateGraph(State)` | 创建一张图的画布 | `fig = plt.figure()` |
| `add_node("agent", agent)` | 加一个节点（工位） | 流水线加一道工序 |
| `add_edge(START, "agent")` | 加一条**固定**连线 | 传送带 |
| `add_conditional_edges(...)` | 加一条**看情况走哪**的岔路 | if / else |
| `compile()` | 把图纸变成能跑的机器 | 编译 |
| `START` / `END` | 起点 / 终点 | 流程图首尾 |
| `app.invoke({"messages": [...]})` | 跑一次图 | 调用编译好的函数 |

## 7. 记忆

| 词 | 人话 |
| --- | --- |
| `MemorySaver()` | 把状态存内存里（重启就没） |
| `checkpointer` | "存档器"：每走一步存一下 |
| `thread_id` | 会话身份证，同一个 id = 同一段记忆 |
| `{"configurable": {"thread_id": "…"}}` | 调用时告诉图"用哪个会话" |
| `.get_state(config)` | 查看某个会话当前存了什么 |

## 8. 读代码三遍法（这是真正的方法）

### 第一遍：念出中文

```python
chain = prompt | get_llm() | StrOutputParser()
# 念：链 = 提示词 → 模型 → 取文本
```

### 第二遍：标出每一步的「输入 → 输出」

| 步骤 | 输入 | 输出 |
| --- | --- | --- |
| `prompt` | 字典 `{"question": …}` | 组装好的提示词 |
| `get_llm()` | 提示词 | 消息对象（AIMessage） |
| `StrOutputParser()` | 消息对象 | 纯文本（str） |

### 第三遍：改一个词，看变化

| 改动 | 会看到什么 |
| --- | --- |
| 删掉 `StrOutputParser()` | 打印出来变成 `content='…'` 那一坨 |
| `temperature=0` → `1` | 同一问题答案每次都不同 |
| L7 里 `"tools"` 改成 `END` | 图不再循环，模型永远拿不到工具结果 |
| L7 里 `add_edge("tools", "agent")` 删掉 | 工具执行完图就停了，没有最终回答 |

> **"改一处看变化"是最快的理解方式**，比读十遍文档有用。

## 9. 练习：逐行翻译（检验你是否真懂）

### 我做的示范（`04.py`）

```python
import sys
from pathlib import Path

# 把上上级目录加入搜索路径（为了能 import 到 config）
sys.path.insert(0, str(Path(__file__).resolve().parent.parent))

from langchain_core.tools import tool   # 导入"工具装饰器"
from config import get_llm              # 导入"创建模型"的函数


@tool                                   # ① 把这个函数注册成"工具"
def add(a: int, b: int) -> int:         # ② 两个整数参数，返回整数
    """计算输入进来的两数之和"""          # ③ 给模型看的说明书
    return a + b


# 创建模型，温度=0（最稳定），并告诉它"你有 add 这个工具"
llm = get_llm(temperature=0).bind_tools([add])

# 问模型（注意：模型不会真的算，它只会发"我要调 add(1, 2)"的请求）
result = llm.invoke("帮我算一下 1 + 2 等于多少")

# 打印模型发来的"调用请求"
print(result.tool_calls)
```
