# 第一部分：6 行 import 到底在拿什么

## 先搞懂 import 语法本身

```python
from 包.模块 import 名字1, 名字2
```

翻译成中文：

> 去 `包.模块` 这个文件里，把 `名字1` 和 `名字2` **搬**过来，之后就能直接用这两个名字。

**关键认知：import 只是"搬名字"，它本身不执行业务逻辑。**

## 逐个拆（07.py 的第 6~14 行）

| 行 | 语句 | 从哪搬 | 搬来了什么 | 它是**什么类型** |
| --- | --- | --- | --- | --- |
| 6 | `from typing import Annotated, TypedDict` | Python **自带**的 `typing` | `Annotated` = 给类型贴标签的工具<br>`TypedDict` = 规定字典有哪些键 | 都是 typing 里的**工具（类/函数）** |
| 8 | `from langchain_core.messages import AnyMessage, HumanMessage` | LangChain 核心包的"消息"模块 | `AnyMessage` = "任何消息"的类型别名<br>`HumanMessage` = 用户消息 | 一个**类型别名** + 一个**类** |
| 9 | `from langchain_core.tools import tool` | 同上，工具模块 | `tool` = 把函数变成工具 | 一个**装饰器**（本质是函数） |
| 10 | `from langgraph.graph import END, START, StateGraph` | LangGraph 的"图"模块 | `END` / `START` = 图的终点/起点标记<br>`StateGraph` = 建图的类 | **两个常量** + 一个**类** |
| 11 | `from langgraph.graph.message import add_messages` | 图模块的"消息"子模块 | `add_messages` = 累加函数 | 一个**函数** |
| 12 | `from langgraph.prebuilt import ToolNode` | LangGraph **预制品**（prebuilt）模块 | `ToolNode` = 现成的"执行工具"节点 | 一个**类** |
| 14 | `from config import get_llm` | **你自己写的** `config.py` | `get_llm` = 创建模型的函数 | 一个**函数** |

> 💡 记住这张表，你就知道每个名字"能干几种事"：
> - 是**类** → 可以 `Xxx(...)` 创建对象
> - 是**函数** → 可以 `xxx(...)` 调用
> - 是**常量** → 直接拿来用，不能加括号

# 第二部分：5 个 Python 代码模板

LangChain 代码里 90% 的行都逃不出这 5 种写法。认出来是哪一种，就懂一半了。

## 模板 1：`名字 = 类(参数)` —— 创建一个对象

```python
g = StateGraph(State)      # 用 State 这份"图纸"，创建一张空图
app = g.compile()          # 把图编译成"能跑的机器"
llm = get_llm()            # 创建模型对象
```

> 类比：`f = open("a.txt")`、`lst = list()`

## 模板 2：`对象.方法(参数)` —— 让对象做一件事

```python
g.add_node("agent", agent)        # 让图 g 增加一个节点
result = llm.invoke("你好")        # 让模型 llm 回答一次
g.add_edge(START, "agent")        # 让图 g 加一条边
```

> 点号 `.` 后面跟的，就是"这个对象能做的一件事"。

## 模板 3：链式调用 —— 一句里连着做两件事

```python
llm = get_llm(temperature=0).bind_tools(TOOLS)
```

这句其实是两步，拆开看：

```python
tmp = get_llm(temperature=0)    # ① 先创建模型
llm = tmp.bind_tools(TOOLS)     # ② 再给它装上工具
```

> 因为 `get_llm(...)` 返回的是一个模型对象，这个对象马上又能 `.bind_tools(...)`。

## 模板 4：`对象 | 对象` —— 管道

```python
chain = prompt | llm | StrOutputParser()
```

`|` 在 LangChain 里被**重载**了：**左边跑完的输出，自动变成右边的输入**。

## 模板 5：`@装饰器` —— 给函数"加工"

```python
@tool
def add(a, b):
    ...
```

等价于：

```python
def add(a, b):
    ...
add = tool(add)     # 把原函数塞进 tool()，换成一个"工具对象"
```

> `@tool` 就是把普通函数**包装**成模型能识别的工具。

# 第三部分：逐行讲 07.py 的后半部分

## ① 定义状态

```python
class State(TypedDict):
    messages: Annotated[list[AnyMessage], add_messages]
```

拆开说：

- `class State(TypedDict)` = 定义一个类，"图纸"来自 `TypedDict`
  - ⚠️ **不是"继承字典类"**。更准确：它**声明"这个字典必须有哪些键"**，运行时还是个普通 dict
- `messages: ...` = 声明一个键叫 `messages`
- `list[AnyMessage]` = 这个键的值是"消息列表"
- `Annotated[...]` 里第二个参数 `add_messages` = **额外贴的一个标签**

**最关键的细节**：

```python
Annotated[list[AnyMessage], add_messages]
#                                  ↑ 没有括号！
```

`add_messages` 在这里**没有被调用**，它只是被**贴上去当标签**，意思是：

> "当有新消息来了，请用 `add_messages` 的方式合并（**追加**），而不是整个覆盖掉。"

真正调用它的是 **LangGraph 内部**，不是你。

## ② 定义工具

```python
@tool
def add(a: int, b: int) -> int:
    """计算两个整数之和。"""
    return a + b
```

| 部分 | 作用 |
| --- | --- |
| `@tool` | 包装成"工具对象" |
| `a: int, b: int` | 告诉模型参数是整数（模型据此生成正确参数） |
| `-> int` | 返回整数 |
| `"""计算两个整数之和。"""` | **给模型看的说明书**——决定它会不会用这个工具 |

## ③ 工具列表 + 模型装备

```python
TOOLS = [add]                                        # 普通 list，装着工具对象
llm = get_llm(temperature=0).bind_tools(TOOLS)       # 创建模型 + 告诉它有哪些工具
```

## ④ 节点函数（agent）

```python
def agent(state: State) -> dict:
    return {"messages": [llm.invoke(state["messages"])]}
```

拆开：

| 片段 | 意思 |
| --- | --- |
| `def agent(state: State) -> dict` | 输入一个 state，返回一个 dict |
| `state["messages"]` | 从状态里取出历史消息 |
| `llm.invoke(...)` | 让模型基于历史回答一次 |
| `[回复]` | 包成列表 |
| `{"messages": [...]}` | 作为"状态更新"返回 → LangGraph 会**累加**进 state |

**注意**：节点函数**不直接修改** state，而是**返回一个更新字典**，由 LangGraph 帮你合并。

## ⑤ 条件边函数（should_continue）

```python
def should_continue(state: State) -> str:
    last = state["messages"][-1]                  # 取最后一条消息
    if getattr(last, "tool_calls", None):         # 安全看它有没有 tool_calls
        return "tools"                            # 有 → 去 tools 节点
    return END                                    # 没有 → 结束
```

| 片段 | 意思 |
| --- | --- |
| `state["messages"][-1]` | 最后一个元素（-1 = 倒数第一个） |
| `getattr(last, "tool_calls", None)` | "取 last 的 `tool_calls` 属性，**没有就返回 None**" |
| `return "tools"` | 返回的是**节点名字的字符串** |
| `return END` | 返回常量 END |

## ⑥ 建图四步

```python
g = StateGraph(State)                # 1. 建空图（图纸是 State）
g.add_node("agent", agent)           # 2. 加节点
g.add_node("tools", ToolNode(TOOLS)) # 3. 再加一个"执行工具"的节点
g.add_edge(START, "agent")           # 4. 加边：起点 → agent
g.add_conditional_edges(             # 5. 加岔路
    "agent",
    should_continue,
    {"tools": "tools", END: END},
)
g.add_edge("tools", "agent")         # 6. 加边：tools → agent（形成循环）
app = g.compile()                    # 7. 编译
```

> ⚠️ **两个 `agent` 不是一回事**：
> `g.add_node("agent", agent)`
> 第一个 `"agent"` 是**字符串名字**（图纸上的标签）；
> 第二个 `agent` 是**函数对象**（真正的工位）。

## ⑦ 调用

```python
result = app.invoke({"messages": [HumanMessage(content="帮我算 123 + 456")]})
print(result["messages"][-1].content)
```

| 片段 | 意思 |
| --- | --- |
| `HumanMessage(content="...")` | 把你的问题包装成"用户消息对象" |
| `{"messages": [...]}` | 初始状态（一个字典） |
| `app.invoke(...)` | 跑一次图 |
| `result["messages"][-1]` | 跑完后状态里的最后一条消息 |
| `.content` | 它的文字 |
