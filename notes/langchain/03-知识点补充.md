## A1 · 函数是"一等公民"（函数能当参数、当返回值）

### 是什么

在 Python 里，**函数名不带括号时，它就是一个"值"**——可以像数字、字符串一样，存进变量、传给别的函数、甚至被返回出来。

### 语法

```python
def double(x):
    return x * 2

# 1) 函数名不带括号 = 一个值
f = double          # 注意：没有 ()
print(f)            # <function double at ...>

# 2) 存进变量后，加括号就能调用
print(f(5))         # 10

# 3) 当成参数传给别的函数
def apply(func, values):
    result = []
    for v in values:
        result.append(func(v))     # 调用"传进来的那个函数"
    return result

print(apply(double, [1, 2, 3]))    # [2, 4, 6]
```

### 你在哪见过它（只是没意识到）

- `sorted(列表, key=len)` —— `len` 就是被当成参数传进去的函数
- `@tool`、`@timer` —— 装饰器本质就是"把一个函数传给另一个函数"

### 关键区分

| 写法 | 含义 |
| --- | --- |
| `double` | 函数本身（一个值） |
| `double(5)` | **调用**函数，得到结果 |

> → 学完做：**练习 01、02**（02 就是"函数返回函数"）

## A2 · TypedDict（给字典规定"键"）

### 是什么

普通字典太自由（想放什么键就放什么键）。`TypedDict` 用**类型注解**规定："这种字典必须有哪些键、每个键是什么类型"。

### 语法

```python
from typing import TypedDict


class Movie(TypedDict):
    title: str
    year: int
    rating: float


# 用法和普通字典一模一样（用下标，不是点）
m: Movie = {"title": "星际穿越", "year": 2014, "rating": 9.4}
print(m["title"])          # 星际穿越
```

### 和 dataclass 的区别（你学过 23-dataclass）

| | dataclass | TypedDict |
| --- | --- | --- |
| 是什么 | 一个真正的**类**（有构造方法） | 只是**类型提示**，运行时就是普通 dict |
| 访问 | `m.title`（点） | `m["title"]`（下标） |
| 用在哪 | 自己造的数据容器 | 描述"别人给我的字典长什么样" |

### 为什么 Agent 代码里用它

LangGraph 的 `State` 就是一个 `TypedDict`——它规定图里流动的"状态字典"必须有哪些键。

> → 学完做：**练习 07**

## A3 · Annotated（给类型"贴标签"）

### 是什么

`Annotated[类型, 元数据]` = 给一个类型**贴一个标签**。**运行时不改变任何行为**，标签只是"额外说明"。

### 语法

```python
from typing import Annotated, get_type_hints

# 给 str 贴上"用户输入"这个标签
UserText = Annotated[str, "用户输入"]


def read(text: UserText) -> str:
    return text


# 用 get_type_hints 把标签读出来（注意 include_extras=True）
hints = get_type_hints(read, include_extras=True)
print(hints["text"].__metadata__)      # ('用户输入',)
```

### 关键：标签可以是一个"函数"

```python
def merge(left, right):
    return left + right


Messages = Annotated[list, merge]      # 标签是 merge 这个函数！
```

### 这就是 LangGraph 里最难那一行的真相

```python
messages: Annotated[list[AnyMessage], add_messages]
#         └── 类型是 list ──┘  └── 标签是"累加函数" add_messages ──┘
```

**翻译成人话**：`messages` 这个字段是列表，而且**新数据来了要用 `add_messages` 的方式累加进去，而不是覆盖**。

> → 学完做：**练习 08、09**

## A4 · getattr / hasattr / setattr（按"名字"访问属性）

### 是什么

平时写 `obj.name` 是**写死**属性名。但有时属性名是**运行时才知道的**（存在变量里），这时要用三兄弟：

| 函数 | 作用 |
| --- | --- |
| `getattr(obj, "名字", 默认值)` | 取属性；**不存在时返回默认值而不报错** |
| `hasattr(obj, "名字")` | 判断有没有这个属性，返回 True/False |
| `setattr(obj, "名字", 值)` | 设置属性（等同 `obj.名字 = 值`） |

### 语法

```python
class User:
    name = "小明"


u = User()
print(u.name)                          # 小明（写死属性名的写法）
print(getattr(u, "name", "匿名"))       # 小明
print(getattr(u, "age", "未知"))        # 未知 ← 没有 age，用默认值兜底
print(hasattr(u, "age"))               # False
```

### 为什么 Agent 代码里用它

判断一条消息"是不是想调工具"：

```python
last = state["messages"][-1]
if getattr(last, "tool_calls", None):
    # 这条消息上有 tool_calls 属性 → 模型想调工具
    ...
```

## B1 · LangChain 调用模型：invoke 和消息对象

### 是什么

`ChatOpenAI` 是"模型对象"；`.invoke(文本)` 是"同步问一次"；返回的是**消息对象**，文本在 `.content` 里。

### 语法

```python
from config import get_llm

llm = get_llm()
result = llm.invoke("你好")      # 问一次，等结果
print(result)                    # AIMessage(...一大堆...)
print(result.content)            # 只有文本
```

### 记住

- `invoke` = 一次完整请求，会等结果（同步）
- 返回的不是字符串，是消息对象 → 文本要 `.content`

> → 学完做：**L1**

## B2 · 提示词模板 ChatPromptTemplate

### 是什么

把"固定的提示框架"和"每次变化的输入"分开。`("角色", "内容")` 是一个元组，`{变量}` 是占位符。

### 语法

```python
from langchain_core.prompts import ChatPromptTemplate

prompt = ChatPromptTemplate.from_messages(
    [
        ("system", "你是一位耐心的 Python 老师"),   # 角色：system（设定）
        ("human", "{question}"),                    # 角色：human（用户）
    ]
)

chain = prompt | get_llm()                          # 先不管 | 是什么，B3 讲
result = chain.invoke({"question": "什么是闭包？"})  # 用字典给 {question} 填值
print(result.content)
```

### 常用角色

| 角色 | 含义 |
| --- | --- |
| `"system"` | 给模型定规矩（人设、规则） |
| `"human"` | 用户说的话 |
| `"ai"` | 助手之前说过的话（做 few-shot 用） |

> → 学完做：**L2**

## B3 · LCEL 管道 `|`

### 是什么

用 `|` 把多个"步骤"串成一条流水线：**前一步的输出，自动变成后一步的输入**。

### 语法

```python
chain = prompt | llm | StrOutputParser()
#        提示词  →  模型  →  解析
```

```python
from langchain_core.output_parsers import StrOutputParser

chain = prompt | get_llm() | StrOutputParser()
out = chain.invoke({"question": "什么是闭包？"})
print(out)                      # 纯文本，不是消息对象
```

### 每一步的输入输出

| 步骤 | 输入 | 输出 |
| --- | --- | --- |
| `prompt` | 字典（给变量填值） | 组装好的提示 |
| `llm` | 提示 | 消息对象（AIMessage） |
| `StrOutputParser` | 消息对象 | **纯文本** |

> → 学完做：**L3**

## B4 · 工具：@tool 与 bind_tools

### 是什么

"工具" = 一个带说明的普通函数。模型**不会自己执行**它，只会返回一个"调用请求"（`tool_calls`），执行是**你的代码**的事。

### 语法

```python
from langchain_core.tools import tool


@tool                              # ① 装饰器
def add(a: int, b: int) -> int:    # ② 类型注解（告诉模型参数长什么样）
    """计算两个整数之和。"""          # ③ docstring（告诉模型这工具是干嘛的）
    return a + b


llm = get_llm(temperature=0).bind_tools([add])   # 把工具"交给"模型

result = llm.invoke("帮我算 1 + 2")
print(result.tool_calls)
# [{'name': 'add', 'args': {'a': 1, 'b': 2}, 'id': ..., 'type': 'tool_call'}]
```

### 关键理解

- `bind_tools` 之后，模型"知道"有哪些工具可用
- 模型想用工具时，回复里是 `tool_calls`（调用请求），**不是** `content`
- 真正执行 `add(1, 2)` 的是你的代码（LangGraph 里由 `ToolNode` 做）

> → 学完做：**L4**

## B5 · 结构化输出 with_structured_output

### 是什么

让模型的回复**直接变成对象**（而不是一段文字）。

### 语法

```python
from pydantic import BaseModel, Field


class Movie(BaseModel):
    title: str = Field(description="片名")
    year: int = Field(description="上映年份")


structured = get_llm().with_structured_output(Movie, method="function_calling")
movie = structured.invoke("《流浪地球》是 2019 年的科幻片")

print(movie.title)     # 流浪地球（直接 .属性 取值）
print(movie.year)      # 2019
```

### ⚠️ DeepSeek 的坑（你笔记 24 里也有）

`method` 参数**必须写 `"function_calling"`**，因为 DeepSeek 不支持默认的 `json_schema`。
